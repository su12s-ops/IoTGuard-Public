# 四智能体执行与评估改进

2026-10-20。本轮修改执行效率与可观测性，不修改风险真值、人工审批或设备写权限。

## 执行变化

- 每个角色保留 `executions` 历史及累计耗时、响应次数；原顶层状态继续表示最近一次执行，兼容既有读取。每轮的 `requests` 记录请求序号、输入字符数、预算、耗时、错误类型和实际返回用量。不保存 API 凭据。
- `usage.llm_requests` 是实际派发次数，包含失败和超时；`llm_calls` 保留收到并消费响应的旧含义。并发请求在发送前原子预占预算。迟到响应不会继续工具调用或写库，无法取得的 token 用量不编造。
- 专家阶段为最终决策保留 `min(300 秒, 总预算的 25%)`。专家本身仍有角色期限；反馈纠错共享该期限。预留不是额外延长总预算。
- 结构校验只进行一次定向反馈纠错，反馈带原报告，不再因同一结构错误重新开始调查。事实引用纠错禁用工具，使用原报告与已有证据。网络失败仍按原有有界策略处理。
- 提示要求复用预取证据、缩短解释和引用原始证据 ID，避免重复日志和公告全文。保留输出上限 32768，避免未经真实验证就截断现有有效报告；接口明确返回长度截断时拒绝当成成功。
- 补查预算不足时保留未解决状态；失败、延期或返回完全相同报告时不再进行完整二次决策。不同报告仍需决策与原有事实门禁；报告变化不等于获得新事实。
- 决策提示明确 logread 历史丢失量不可知的边界；技术门禁拦截未建立计量能力却承诺重启后得到数值/零丢失的计划。此检查是保守辅助检查，不能替代人工判断全部自然语言建议。
- 页面区分流程结束、角色状态、审核结果与处置计划，并提供轮次与请求明细。历史记录没有新增字段时明确标示未记录，不伪造完整历史。

## 2026-10-21：上下文与角色预算（只收敛质量，不新增角色）

- **提示词预算**：`app/services/unified/context_budget.py` 把「提示词多大」变成可强制的
  运行约束。每个角色有估算 token 额度（默认 40000–56000），请求前闸门超限即显式降级
  （`context_budget_exceeded`），不再把百万字符提示词发给模型换回 400 后浪费重试。
- **可引用 ID 有界渲染**：漏洞与决策提示词只列 80 条样例 + 全集条数 + 截断标记；
  全集仍由校验器在服务端比对。这是 7,233,731 字符请求的直接根因（28.5 万条 ID 全量序列化）。
- **角色 token 配额**：`BudgetState.role_token_limits` 给四个角色分别设上限
  （60k/55k/40k/60k），`UsageMeter` 按角色计量并独立判定；run 级上限仍是硬顶。
  实测资产角色曾单角色用掉 266,072 tokens，导致后三角色 0 次调用即降级。
- **预算错误语义**：`UsageMeter` 记录 `budget_exhausted_kind`（calls/tokens）与
  `budget_exhausted_role`，提示词分别报「调用预算」或「token 预算」——此前 token
  击穿也报「调用预算已用尽（上限 40）」，把排障引向错误方向。
- **观测**：`agent_logs` 每个角色新增 `prompt_estimated_tokens / prompt_chars`；
  `usage_json` 新增 `role_usage / role_token_limits / budget_exhausted_kind`。
- **对照实验脚手架**：`single_agent` 策略（`RunContext.strategy`）让同一张图只调用
  决策角色、共用同一确定性预取事实，用于「四智能体 vs 单智能体」的同事实对照；
  记录器与统计器见[智能体质量基准](AGENT_QUALITY_BENCH.md)。

## 分流与评估

正式入口继续完整四角色。每次强制完整运行额外记录 `routing_recommendation` Trace，保留规则建议的简化路径和实际执行路径，供对照分析。未用新规则自动批准风险或修改修复授权。

离线对照统计器：

```powershell
python backend/scripts/evaluate_agent_comparison.py comparison.jsonl --output comparison-result.json
```

每行是一个已经完成的实验观测，必填字段：

- `case_id`：固定案例编号。
- `facts_sha256`：三种策略共同使用的输入事实快照 SHA-256。
- `repeat`：同一案例的重复实验编号。
- `strategy`：`rules`、`single_agent` 或 `four_agents`。
- `expected`：实验前由独立人工确定的标准答案字段映射，如 `impact_status`、`recommended_action`。
- `actual`：对应输出字段；失败可以为空。
- `status`：成功为 `succeeded`，超时/失败/降级保留实际状态。
- 可选观测：`latency_seconds`、`total_tokens`、`invalid_evidence_refs`、`human_review_minutes`。未测量时省略或 null，不能填 0。

只对三个策略输入事实相同、标准答案相同且齐全的分组做比较；失败计入准确率分母，不混入成功样本。未配对组单独计数，缺失用量保持 null。拒绝重复记录与组内变更真值；结果文件不得覆盖已有实验。

统计器不运行真实模型、不产生新实验数据、不自动开启正式简化路径。单元测试验证统计口径，不能作为四智能体优于规则或单模型的证据。真实质量、耗时改善及人审工作量仍须用独立案例重复测量。

## 部署边界

代码和页面构建完成后，运行中的 Python 服务需要受控重启才加载变更；本轮不自动重启承载其他采集改动的服务。开发前端可热更新，部署前端须更新构建产物。已有数据库无需迁移，新字段保存在原 JSON 列中。
