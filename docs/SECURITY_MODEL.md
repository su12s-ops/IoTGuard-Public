# 权限与风险治理

本规范描述当前正式模型，执行以代码中的确定性校验为准。

## 认证域

控制平面使用 `LINUXGUARD_CONTROL_TOKEN` / `X-Control-Token`，覆盖业务状态变更、情报同步、模型分析、任务授权、审批与执行。未配置或不匹配时拒绝，不暴露期望令牌。

节点平面使用独立 `LINUXGUARD_COLLECTION_NODE_TOKEN` / `X-Collection-Node-Token`；附加节点使用相应后缀变量。节点只能领取其所属任务和回传结果，不能审批风险或修复。设备私钥由节点本地环境变量引用，不进入 API 数据库或镜像。

## 独立写开关

| 配置 | 作用域 | 默认值 |
|---|---|---|
| `LINUXGUARD_ENABLE_DEVICE_REPAIR` | OpenWrt 设备包修复 | `0` |
| `LINUXGUARD_ENABLE_UBUNTU_LAB_REPAIR` | 独立 Ubuntu 克隆实验写 | `0` |

两个域互不授权。开关不能替代身份、风险治理、精确计划审批、执行节点与恢复检查。默认部署保持关闭。

Ubuntu 克隆实验还须满足：显式资产白名单（空白即拒绝）、对象级治理、计划与审批哈希一致、官方原文哈希及 24 小时时效、15 分钟内预演、节点独立许可、隔离克隆与恢复证明、真实 root 执行权限。后端排队和节点领取独立复核；只读预演通过不代表允许安装。

## 四智能体与人审

正式流程为 `asset_investigator → vulnerability_analyst ∥ runtime_analyst → decision_planner`，`LINUXGUARD_UNIFIED_PIPELINE=on`；正式入口 `/api/analysis`，写入器 `unified.adapter.formal_sink`。off / shadow 拒绝正式请求，没有旧 LLM 回退。默认每批一个对象、最多四个、串行执行；活动批次期间拒绝第二批。

- 模型建议不代替操作员裁定；确认风险不等于批准修复。
- 分开表达静态适用性、触发条件、运行时活动和已证实利用。无事件不证明不受影响。
- 风险升降相对明确基线，软件包升级或降级单独记录；历史原值不批量覆盖。
- 优先级综合官方情报、适用性、暴露和证据覆盖；情报不可用不等于低风险。
- 补证使用固定只读 Collector；申请、授权、原始清单、再研判与缺口分别留痕。
- 官方纠正、原风险、旧候选及授权追加保存；旧候选失效时审批不继承，任务 PATCH 和风险重算不能恢复其执行资格。
- `reanalysis_required` 未获得当前正式结论前不可确认。人审须提供操作员、理由及 `expected_status`；历史 inactive 通过独立 historical-adjudication 追加裁定并保持 inactive。
- 分别解释静态、运行时、官方覆盖和模型方差；同事实重跑不伪造风险变化。
- 修复后复评要求当前清单完整，追加独立事件，不改写历史风险或审批。

## 执行与恢复

Harness 绑定计划哈希、目标与连接签名、Collector 摘要、资产锁、工具预算和产物哈希。SSH 主机身份不一致必须失败，不降级；重试不能自动重放设备写。

模型调用、工具调用、拒绝及裁定留审计。纠正保留原输出；文件备份不等于软件包或虚拟机恢复。数据库恢复须停止新任务、排空 worker、保存增量审计，并核验代码与一致性备份；单改模式开关不构成回滚。
