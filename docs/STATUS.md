# 产品状态

更新日期：2026-10-19。本文描述当前实现及边界，替代开发阶段报告；不作为全部设备或漏洞的安全验收证明。

## 已实现

- 设备发现、身份识别、组件建档、多源情报、风险与修复工作流、Trace 和 IoT 工作台。
- 唯一正式四智能体；对象级人审、只读补证、历史裁定与修复后复评。
- OpenWrt 25.12.6 / 内核 6.12.112 的完整 182 包采集、日志回传、升级和当前版本快照恢复验证。
- Zephyr RTOS 4.4.2 / 应用 0.3.0 的 QEMU 构建、HTTP 身份、应用固件回退、崩溃恢复及复采。
- Zephyr 281 条、OpenWrt 9 条官方公告快照存储、来源约束、哈希与保守版本查询。
- Ubuntu 独立克隆三个 curl 同源包修复与复采；不代表源 Ubuntu 或 IoT 设备已修复。
- 非 root API 与 nginx Docker 部署；设备凭据及内核传感器在容器之外。

## 待完成

1. 官方公告持续同步，以及公告、包修订、板型、Kconfig、链接及可达性证据的设备适用性闭环。版本命中仍是候选。
2. 基于精确适用漏洞的 OpenWrt 专属修复与完整业务恢复验收。系统升级不等于全部漏洞修复。
3. Zephyr 签名 OTA、镜像真实性、目标板校验、设备侧更新及失败恢复适配器。
4. 实体硬件验证。OpenWrt 为 VMware、Zephyr 为 QEMU；模拟温湿度不作为安全证据。
5. 长期运行、宿主重启自动恢复与丢失统计。logread 周期拉取的环形缓冲历史丢失不可知；Falco 内核丢失计数尚有不可用项。
6. 完整安全扫描。历史 Mimosa 为 partial / inconclusive，未取得全项目覆盖结论。

## 运行与部署边界

实时开发前端 5173 对接宿主 API 8000；Docker 前端 18080 对接独立 API 18000。已有 Docker 验证库为独立快照，不接收实时设备更新；空库新部署也不会自动获得原设备数据。

2026-10-19 检查时，实时 API、采集节点、Falco 与 OpenWrt logread 在线，运行时证据新鲜；仅覆盖该检查窗口。

最近部署因镜像源拒绝基础镜像请求，采用已有本地应用镜像增量更新；容器健康不等于完成全新依赖重建。Compose / Dockerfile 仍为标准构建入口。

## 验收要求

每种设备须独立关联授权与身份、完整清单、官方适用性、补证、风险、修复计划与授权、执行与失败恢复、复采、漏洞复评和业务检查。无法自动执行时进入人工操作与复验，不直接标记已修复。
