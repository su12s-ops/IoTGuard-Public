# 产品状态

更新日期：2026-10-20。本文描述当前实现及边界，替代开发阶段报告；不作为全部设备或漏洞的安全验收证明。

## 已实现

- 设备发现、身份识别、组件建档、多源情报、风险与修复工作流、Trace 和 IoT 工作台。
- 唯一正式四智能体；对象级人审、只读补证、历史裁定与修复后复评。
- OpenWrt 25.12.6 / 内核 6.12.112 的完整 182 包采集、日志回传、升级和当前版本快照恢复验证。
- Zephyr RTOS 4.4.2 / 应用 0.3.0 的 QEMU 构建、HTTP 身份、应用固件回退、崩溃恢复及复采。
- Zephyr 281 条、OpenWrt 9 条官方公告快照存储、来源约束、哈希与保守版本查询。
- Ubuntu 独立克隆三个 curl 同源包修复与复采；不代表源 Ubuntu 或 IoT 设备已修复。
- 非 root API 与 nginx Docker 部署；设备凭据及内核传感器在容器之外。
- OpenWrt 官方 GHSA 情报规范化接入与设备级四态匹配（零 CVE 专用代码，2026-10-19 报告）。
- OpenWrt-Lab 隔离克隆（2026-10-19）：冻结基盘复制、联网前离线身份隔离、S0-CLEAN 快照与真实恢复测试、产品内独立接入（asset 4 / conn 4 / 专用密钥），匹配与风险与原机独立；实验子门禁具备资产范围检查，最终生产/实验写权限域已在 2026-10-20 改为持久登记并独立核验，见 [权限规范](SECURITY_MODEL.md)。

## 待完成

1. 公告、包修订、板型、Kconfig、链接及可达性证据的设备适用性闭环仍需逐项完成。已提供双生态同步脚本及 systemd 定时模板；版本命中仍是候选。
2. OpenWrt-Lab 的 CVE-2026-62947 已完成真实修复、只读续验及 S2→S1→S2 快照恢复；尚未完成人工业务签收。本轮复采仍为精确 fixed，但其他分支候选和运行时覆盖不得继承该单项修复结论。见 [设备验收](DEVICE_ACCEPTANCE.md)与专项闭环报告。
3. 本轮已完成受信任 QEMU 宿主的签名、目标板/身份、镜像与配置摘要校验、失败恢复适配器及独立 guest 实测；设备侧 OTA/安全启动未实现，明确不作为当前虚拟宿主能力声明。
4. 操作员明确本轮仅验收虚拟设备：OpenWrt 为 VMware、Zephyr 为 QEMU。实体硬件移至后续范围，模拟温湿度不作为安全证据。
5. 长期运行、宿主重启自动恢复与丢失统计。logread 周期拉取的环形缓冲历史丢失不可知；Falco 服务已在本轮恢复，但内核丢失计数仍有不可用项，不能记为零丢失。
6. 完整安全扫描。历史 Mimosa 为 partial / inconclusive，未取得全项目覆盖结论。

## 运行与部署边界

实时开发前端 5173 对接宿主 API 8000；Docker 前端 18080 对接独立 API 18000。已有 Docker 验证库为独立快照，不接收实时设备更新；空库新部署也不会自动获得原设备数据。

2026-10-19 晚间收尾检查：宿主 API 曾停止，本轮经一致性备份后恢复；既有 m45 采集节点自动重连，OpenWrt 原机与 Lab 的 logread 周期采集及新清单成功。Zephyr 重启前后 HTTP 回归通过。Ubuntu Falco 经管理员启动和受限 VMnet 回传恢复后，真实验收事件已入库；健康接口显示三个传感器健康、证据新鲜。其丢失计数仍不可用，不等于 0；结果仅覆盖本轮检查窗口。

2026-10-19 曾因镜像源拒绝请求采用本地镜像增量更新；2026-10-20 已恢复标准 Compose 双镜像构建并锁定升级依赖。镜像构建通过不等于已迁移真实设备库。
