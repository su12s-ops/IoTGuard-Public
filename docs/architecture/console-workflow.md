# 控制台自动流程

Docker 页面及 API 入口统一为 `http://127.0.0.1:18080`。控制台代理在服务端注入授权，不向浏览器下发实际控制令牌。

点击“开始”后，`POST /api/console/start` 创建持久化 `console_workflow`，后台顺序获取对应设备生态的官方情报、匹配版本、计算风险，复用 `rounds.execute_round` 和唯一正式 `analysis.create_run` 入口进行四智能体研判。候选较多时按现有批次上限提交，具体调度与预算由执行模式决定；风险治理和设备修复审批保持原门禁。重复点击复用当前流程，不重复发起模型任务。

`GET /api/console/current` 返回真实阶段、各步骤状态、关联轮次及报告进度。前端每 3 秒读取；关闭页面不停止后台。阶段进度按五步展示，模型阶段结合报告进度；等待人工审核为 80%，相关对象全部裁定后为 100%。无候选会明确跳过智能体及审核；失败停止并保留原因。后台准备任务被服务重启中断时如实标记中断，不重放操作。

新构建 Compose 默认使用有界 `task_graph` 执行：共享同设备基础调查，2 个风险工作线程共用 2 个模型请求槽位，跨批次继承分析窗口与预算；实际运行、排队、复用和延期分别显示。超出窗口的对象保留为候选，状态为 `partial`，不计为全部处理完。新模式暂时保留人工审核要求。完整实现、回退方式及未完成项见 [有界任务图运行方式](task-graph-runtime.md)；旧的逐风险完整执行仍可通过配置选用。

“刷新本轮”仅在流程、模型、同步及设备任务均未运行时可用：不创建新归档，清理运行数据、轮次、流程、漏洞与公告、全局情报缓存、运行时 JSONL 镜像及 `exp-*.json` 旧结果归档（含元数据）。保留设备台账、软件与服务清单、连接、发现身份、采集传感器及策略配置。持续采集可能在清理后产生新事件。

兼容性：旧 `/experiment/archive`、`/experiment/reset` 仍保留原契约供脚本使用；控制台不再展示归档管理面板。新控制台刷新与旧“先归档再清理”语义独立。
