# 有界任务图运行方式：v6 实现

初始实现：2026-10-25；v6 降级治理：2026-10-26。对应设计：[多智能体运行架构调整方案](multi-agent-design.md)。

## 实际改变

四角色和唯一正式 `formal_sink` 保留。新增 `task_runtime.py` 管理请求、时间与预算，`task_reports.py` 管理作用域、共享报告和来源回执。

- 同设备、同身份/完整清单/服务/业务环境、同覆盖与新鲜度状态下，资产基础调查只执行一次。并行风险等待同一任务，不重复派发。依赖变化、模型配置变化、模式版本或 Schema 变化使旧报告失效。
- 资产任务不携带具体 CVE 或其他风险的协作消息。复用后再次校验证据与输出 Schema，记录原任务、原运行和原快照，模型调用计为 0。
- 同一批中相同事实的共享调查失败后，不再对每个风险重试；保留原失败原因。不同事实或操作员发起的新批次可以重新调查。
- 实验重置保留当前设备清单实际引用、且绑定同一资产的原始 `CollectionEvidence`，删除未引用的历史采集证据，避免台账留下失效引用。不存在的证据不重建、不伪造；损坏证据仍由原校验器拒绝。
- 漏洞与运行时报告仍保留资产、候选和证据窗口的精确作用域。本版不会跨资产共享受影响裁定，也不会把某 CVE 的利用证据套给其他 CVE；公共公告解释的独立分组和运行时报告的逐 CVE 投影属于后续工作。
- 无可逐条核验的运行时证据时，程序返回 `unavailable` 与覆盖限制，省去无事实可分析的模型请求。可用的历史单条证据仍可分析，并受现有新鲜度校验约束；历史汇总不当作当前安全证据。
- 常规路径关闭同快照上的消息循环、定向复议、自动重复决策和再次调查。具体补证请求保留为既有待授权调查事项；有新证据后可通过原再研判入口创建新任务。
- 输出仍经过结构、证据、候选/风险作用域、风险门禁和计划门禁。新模式暂时强制人工审核，原因是 `task_graph_quality_validation_required`；尚未完成真实质量对照，不自动确认风险。

## v6：消除资源饥饿与交接范围导致的降级

现场失败记录确认了两条具体触发链。其一，旧批次已消费 571975 / 600000 token，调度器仍启动新风险，多个角色在 0 次模型调用时即因 `batch_budget_reserved_for_decision` 或 `batch_model_budget_exhausted` 降级；下一批只剩 28025 token，仍继续创建研判。其二，决策者为当前风险输出正确裁定后，又附加设备级裁定，两次请求后仍触发 `verdict_outside_task_scope`。

现在每个风险启动前，原子预留已有单风险额度：200000 预算 token、16 次请求及至少 480 秒剩余窗口。并行风险各自持有额度，不能抢走另一项决策所需资源；请求实际派发时从预留中划拨，返回后按真实 usage 结算，结束即归还未用额度。等待其他风险归还额度不计为角色失败。无法容纳完整研判时，不创建角色与正式子运行，风险保持候选，轮次明确为 `partial`，原因为 `analysis_budget_insufficient_for_review` 或 `analysis_window_exhausted`。整轮仍保持原 600000 token、160 次请求与 30 分钟上限；这不承诺所有候选均能在同一轮完成。

预算账本 `reserved_tokens` 包含尚未消费的整项预留与在途请求预留，实际请求数不因准入增加。运行快照另外分开暴露 `reserved_tokens`（在途请求）、`review_reserved_tokens`（整项剩余额度）、`admitted_reviews` 与 `admission_stop_reason`。角色失败或迟到响应仍如实计量，不能通过释放预留清掉真实消耗。

协作统一为资产报告复用、漏洞/运行时专家并行核验、决策收敛的报告交接。任务图的系统指令和输出 Schema 均要求 `messages=[]`，避免通用提示词鼓励提问，而当前模式没有消息循环处理这些问题。漏洞角色优先使用已有程序预取事实，只有缺项、冲突或语义歧义时查工具。决策 Schema 根据当前风险生成 `object_id` 常量及恰好一条裁定的约束；模型可通过原有有界结构纠错修正输出，程序不删除多余裁定来伪造成功。原证据、作用域、语义及人审门禁继续执行。

## 2026-10-26 维护：租约隔离与缓存恢复

每次共享任务执行使用独立租约标识。同批次内，旧执行过期后即使迟到返回，也不能完成或置失败新执行的任务。完成写入同时在数据库核对租约、运行状态与有效期；租约失效返回 `shared_task_lease_lost`，其报告不进入后续决策，回执标记 `lease_lost`。角色最终日志显示降级，先前真实模型调用、耗时和用量继续保留，不能因拒绝迟到结果而清零。

复用报告先验证输出 Schema，再执行原有证据与作用域校验。合法 JSON 但字段缺失、字段类型错误或顶层类型错误时，使用当前作用域进行受原预算和截止时间约束的新执行，不修改原缓存回执，也不把损坏报告当成有效结果。

隔离回归覆盖同批次过期执行的迟到成功和迟到失败、替代任务的最终报告、角色日志与计量，以及多种缓存格式异常。协议超时测试使用有效的 Anthropic 文本响应桩，仍校验 SDK 超时上限和关闭内部重试。上述测试不调用真实模型，不代表现场部署或研判质量验证。

上述租约维护阶段的本地验证环境为 Windows / Python 3.14.4：后端全量回归 1248 项通过（899.77 秒，6 条既有测试夹具 `datetime.utcnow()` 弃用警告）；全量执行期间补充的角色日志修正，另经 49 项专项复验通过。前端 Node 测试 12 项通过，生产构建与 44 份 Markdown 的本地链接检查通过。此记录早于 v6 协作调整，不作为 v6 全量测试或现场质量结论。

## 初始运行限制

| 项目 | 实现值 |
|---|---|
| 就绪风险工作线程 | 2；独立数据库会话 |
| 单后端进程在途模型请求 | 2；不同批次共享，迟到 HTTP 响应也占用槽位直至返回 |
| 单模型请求 | 最多 180 秒，等待槽位计入期限 |
| 单角色任务 | 最多 240 秒，含等待共享任务、调查和纠错 |
| 单风险 | 最多 480 秒，为决策预留部分时间 |
| 完整风险准入 | 预留 200000 预算 token 与 16 次请求，剩余窗口至少 480 秒；未用额度归还，不计为实际消耗 |
| 控制台整轮 | 从点击开始计 1800 秒，后续批次继承剩余窗口 |
| 单任务模型请求 | 最多 4 次，最多两轮工具调用，之后无工具收敛；最终报告和引用纠错共用额度 |
| 单风险模型请求 | 最多 16 次，四角色共享 |
| 常规角色上下文 | 估算 16000 token，包含 Schema、指令和累计工具结果；超限显式降级 |
| 工具结果提示词视图 | 新模式单条最多 4000 字符，截断与原始长度明确标记，原数据不改写 |
| 单次输出上限 | 16384 token；截断视为失败，不接受半截报告；GLM-5.3 系列启用 thinking、reasoning_effort=low，并保留工具轮次的原生思考块 |
| 整轮模型预算 | 600000 预算计费 token、160 次请求；为决策保留部分额度 |

预算计费 token 与实际 token 分开：派发前预留估算输入和输出额度，返回后结算真实用量。无响应或无 usage 时保留保守计费并累计“未知用量请求数”，不会把估算记成实际消耗。`analysis_budget` 保存派发、在途预留和结算，跨批次及迟到响应继续计账。

30 分钟控制的是后续分析派发，不承诺 29 项全部完成。情报获取在进度检查点判断期限；正在进行的外部请求仍受来源自身超时约束。预算结束时未启动的风险恢复为候选，轮次和控制台显示 `partial`，不把它们计为已研判。已尝试但角色失败的风险保留失败详情与人审要求。

v2 真实试验发现：资产来源字段约 8.6 万字符导致首轮超限；工具轮数结束后原循环不请求最终报告；原生模型推理占用输出额度。现在来源列表只渲染带总量、哈希和截断说明的样例，原始清单和完整依赖哈希保留。后续真实两项试验中，资产报告完成且复用一次，但其他角色累计对话最高约 12300 估算 token，超过旧 8000 限制；据此调整为 16000，并缩小工具视图。v4 修正此前统一禁用思考的控制方式，按 GLM-5.3 的支持范围选择 enabled/low，详见 [GLM 协议检查](../archive/2026-10-25-model-protocol.md)。请求、时间和整轮预算保持有界；这些参数仍需质量对照校准。

官方情报抓取使用标准证书及主机名验证。现场代理对 Docker TLS 1.3 连接返回 EOF，显式配置 `LINUXGUARD_INTEL_TLS_MAX_VERSION=1.2` 后可正常访问 GitHub 和 Ubuntu 官方接口。该设置仅影响情报抓取，未关闭证书验证。OpenWrt 来源中断时，仅允许使用校验通过的已有官方快照，保留原时间与过期提示。

运行时入库在读取资产与判重前使用 SQLite `BEGIN IMMEDIATE`，防止 WAL 读快照在其他写入提交后升级失败。同步数据库入库端点交由工作线程运行，避免等待写锁时阻塞 ASGI 事件循环。

当前并发协调按仓库现有单 uvicorn 进程部署实现。多进程、多副本部署前须增加跨进程请求限额和原子租约协调，不能直接增加 workers 来放大并发。

## 前端与持久化

控制台进度新增实际运行对象、正在执行的角色、对象耗时、排队数和复用报告数。实际运行来自 `UnifiedAnalysisRun` 与角色 Trace；排队对象不再提前标作 `agent_reviewing`。角色 Trace 只投影生命周期，不冒充已提交报告或真实 token 计量。

v3 在控制台和智能体详情中区分：等待同设备共享报告、等待全局模型槽位、模型请求已发出/等待响应、查询原始证据、处理校验。事件在实际步骤发生时持久化；页面继续按现有 3 秒周期读取，不生成虚假的逐 token 进度或剩余时间。当前步骤耗时、请求/返回数、累计排队与模型等待时间均来自事件时间，多个并行请求的耗时可能重叠。统计只覆盖最近 80 条活动事件，`partial=true` 表示截断，不能当作全量统计。

最近完成的角色显示真实失败原因，并区分上下文超限、预算耗尽、超时、报告截断、证据校验和格式问题。正常的证据不足、来源冲突与人审门禁仍保留原语义，不改写为模型执行失败。

运行时角色直接获得最多六条已登记的原始行为样例，包含真实 ID、时间、来源和截断说明；取样优先候选相关事件，读取时重新核对快照 observation 哈希。样例不能证明未展示行为不存在，具体深查工具仍可用。

本次真实验证发现：旧取证工具查询实时数据库，而引用校验只接受开始时快照；新事件真实存在也会被拒绝，造成纠错重试。v3 给运行时角色独立数据库会话增加快照范围过滤，包含进程树查询；新事件不删除、不自动加入旧快照，留待新快照分析。该约束只应用于新模式的运行时工具。

另一个真实失败是普通行为报告同时输出 `runtime_status=verified` 与 `evidence_freshness=mixed`，两次请求后仍互相矛盾。对于新模式的 `NORMAL` 报告，仅在所有引用 ID 都已登记、快照新鲜度确实为 stale/mixed、且模型的 freshness 与之相同时，程序将状态保守限制为 `stale_verified`。不提升新鲜度，不处理攻击断言，不替换未知引用；仍执行原 Schema 与事实校验。原始与有效报告分别保存在 `normalized_reports`，有效报告有明确归类说明，避免为确定性的状态组合消耗额外模型纠错请求。

新增 `analysis_task` 与 `analysis_budget` 表，由原有 `init_db()` 创建，原业务数据不迁移或重算。任务报告、租约和预算属于衍生运行数据，已加入实验清理顺序。模型重用的有效输出和来源回执也保存在原分析快照中。

## 启用与回退

现场 GLM 配置已在真实历史材料对照后切换为 `openai` 协议与 `https://open.bigmodel.cn/api/coding/paas/v4`，同一模型与密钥。原 Anthropic 链路在复杂决策输入上持续只输出思考并耗尽额度；原生接口通过应用的结构、引用与语义校验。完整复现与限制见 [GLM 协议修复记录](../archive/2026-10-25-model-protocol.md)。接口不自动回退，报告缓存版本为 v6。

- Docker Compose 下，新构建服务默认 `task_graph`；可用宿主变量 `IOTGUARD_REVIEW_EXECUTION=legacy` 保留旧执行方式。两种模式均使用同一正式写入与授权入口。
- 本地 Python 服务读取 `LINUXGUARD_REVIEW_EXECUTION=task_graph`；未配置时保持 `legacy`，样例环境文件已经提供新值。
- 模式在进程启动时确定，不会热切换正在运行的任务。
- 部署涉及重建和替换服务，应在当前运行结束后安排。代码测试、前端构建和镜像构建都不等于运行中容器已切换。
- 模型研判不授予设备写权限。现场已按操作员授权中断旧流程、切换新服务，并保留已落库结果。

前端验证包含生产构建、Node 逻辑测试与 Edge 浏览器端到端测试；API 被拦截的浏览器测试只验证显示与交互。

2026-10-25 历史检查窗口确认采集节点在线、3/3 传感器健康、事件新鲜；2026-10-26 克隆移出平台后的情况以 [当前状态](../status.md)为准。资产 1、2、4 已通过正式只读采集恢复原始清单回执；历史克隆资产 3 尚缺回执，启动其虚拟机的操作被自动审批拒绝，不能视为已恢复。

尚未验证：完整真实模型质量、可推广的提速与 token 降幅、跨资产公共公告解释共享、独立运行时报告的逐风险投影、多实例调度、取消/继续的独立任务 API，以及完整设计中的新旧固定事实配对实验。这些不能用 mock 测试通过代替。

下一次真实对照应在隔离数据库中固定事实与模型配置，按设计文档的场景、准确率、稳定性、完成率、耗时、成本和人审工作量同时评估；保留失败与延期样本。
