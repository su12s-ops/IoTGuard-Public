# Harness 授权补证自动续验

> 历史记录：保留当时的结果、失败与限制，不代表当前部署状态。当前入口见 [项目状态](../status.md)。

在智能体运行详情的补证申请中，选择连接、填写授权人与依据，并勾选“采集成功且事实变化后自动复评一次”。该具体申请授权后，后台每 15 秒检查采集任务；完成后复用原有原始证据哈希、目标绑定、正式来源及原子领取校验，最多自动复评一次。

授权只覆盖该申请的固定 inventory Collector 和一次模型复评；不授权安装、重启或配置修改，不继承到后续申请。旧授权默认不自动复评。无需数据库迁移，续验选择保存在申请 result_json 中。

采集失败进入 collection_failed；事实未变化进入 no_new_evidence，保留原风险审核结论；来源被替换、证据损坏等进入 auto_resume_blocked。页面展示具体原因。后台仅在标准 API 部署启动，collection_only 节点不启动。

本次实现的范围是消除“已经授权采集后仍要手动点击复评”的机械步骤。尚未实现跨申请的长期预授权策略、自动生成所有缺口的采集计划或运行时补证复评。清单不能修复运行时覆盖缺口，未支持的能力仍保留人审说明。未取消人工业务审核或修复审批。

服务重启后启用后台。运行中的模型复评不做强制中断；部署应避开活动复评。进程异常中断的 reanalysis_running 记录保留，不自动重放。

验证：补证与治理回归 47 项通过，四个自动续验场景通过，前端生产构建通过。本轮未对真实设备执行采集或重新调用付费模型。
