## 已验证

- 页面实际显示一台 OpenWrt；Docker 与主机 API 均没有旧克隆连接。
- 网关 `iotguard-lan` 服务和四个命名空间运行，四个设备实际获得 DHCP 租约。
- 四个 HTTP 身份端点及 MQTT CONNECT/CONNACK 可用；两台摄像头实际返回 JPEG，MJPEG 与模拟开关另有协议回归。
- 网关 logread 周期采集恢复上报，Ubuntu Falco 正常上报；可靠性接口不再包含旧克隆传感器。
- 四角色任务图、报告复用、预算账本、证据作用域和前端流程已有隔离回归与有限真实模型实验。成功、降级和失败样本见 [任务图运行方式](architecture/task-graph-runtime.md)。
- 多智能体 v6 已部署：整项预算准入、精确风险输出契约与报告交接替代矛盾的消息指令。原范围失败样本复测、隔离两项完整研判以及正式单项 `3a18c4284001` 均无角色降级；证据缺口和适用性冲突导致的人审继续保留，不能据此宣布所有候选或模型质量已通过。
- 可靠性接口按传感器暴露 logread 最近窗口的行数、解析跳过、入库/重复数、截断状态和 `ring_loss=unavailable`；官方覆盖接口明确返回本地快照年龄、SHA256 与状态。它们改善可观测性，不把不可测丢失或离线快照包装成通过。

本轮原始回执、数据库行归档和配置备份仅保存在本机忽略目录，不随公开仓库发布。

## 尚未完成

1. **旧克隆磁盘清理**：VMware 删除命令返回权限不足，目录删除被自动审批阻止；文件仍在磁盘。原机依赖另一个基础磁盘目录，不能整批删除共同父目录。见 [单实例清理记录](archive/2026-10-26-openwrt-single-instance.md)。
2. **原生 eBPF 平台覆盖**：已在原生采集器文档列出实测/失败/未知平台矩阵。当前 OpenWrt 使用 logread；Linux 7.0 行为失败不能视为已支持。实际兼容性仍须在目标内核逐台跑受控事件验收。
3. **长期稳定性与丢失统计**：未取得完整跨平台 24 小时通过结论。logread 环形缓冲历史丢失不可知，Falco 计数受探针实际统计输出限制；新接口会展示窗口解析/截断及 `unavailable`，不会估算丢失量。
4. **多智能体质量与耗时**：质量基准页增加双人独立标签、固定快照、重复次数和配对统计发布门槛。现有标签数量不足，不得宣称普遍提速或更准确；需要补充真实案例及独立标注后执行实验。
5. **官方在线情报**：官方覆盖接口及控制台返回全部记录的本地内容更新时间范围、整体清单 SHA256、完整性和 24 小时 `recent/stale` 指示；年龄按最早记录计算，不表示成功获取时间或远端最新性。未来时间标记 unknown、内容损坏标记 invalid。在线失败不会刷新时间。
6. **设备适用性与业务验收**：版本范围命中仍需结合公告、包修订、构建配置及可达性。新模拟设备未完成真实固件或逐漏洞的正式研判验收。
7. **硬件与 OTA**：本轮没有实体设备验收；QEMU 宿主签名更新不等于设备侧安全启动或实体 OTA。设备验收页现提供逐资产记录模板与端到端 24 小时通过条件，仍需在授权现场执行并归档。

## 状态判断规则

分别检查平台 API、采集节点、每个资产的传感器、证据新鲜度和正式任务终态。`queued_remote` 只表示排队，`completed` 只表示该任务流程结束，`human_review` 仍要求人工处理。无数据或无告警不能自动标为安全。

使用入口见 [部署指南](guides/deployment.md)、[LAN 模拟指南](guides/openwrt-lan.md)和[文档索引](README.md)。历史结果集中在 [归档目录](archive/README.md)，保留失败与边界，不回写成当前通过。
